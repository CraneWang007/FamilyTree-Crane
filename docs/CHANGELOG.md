# 家和万事兴 · 项目变更记录

> 本文件是项目伴随文档之一，与 [关系要求](./RELATIONSHIP_REQUIREMENTS.md) 一起随项目长期维护。
> 项目上线前，每完成一个需求都必须在本文件追加记录；凡是涉及亲属关系、代际、分支、权限、隐私的变化，还必须同步更新《关系要求》。

## 一、维护约定

1. **每次需求必更新**：一个需求从提出到完成，必须在“变更记录”中新增一条，不允许只改代码不记文档。
2. **位置**：新条目写在“二、变更记录”的最上方，按日期倒序排列；同一天内按完成顺序排列。
3. **条目最少包含**：日期、类型、模块、需求来源、变更内容、影响文件、验证方式。
4. **类型统一使用**：`新增`、`优化`、`修复`、`权限`、`数据`、`文档`、`环境`。
5. **上线前复核**：上线前逐条检查本文件与《关系要求》是否覆盖了本次全部需求；未记录的变更不得上线。
6. **历史不可篡改**：已上线的历史条目只允许补充说明，不允许删除或改写原意；需要推翻旧规则时，新增条目并注明替代关系。
7. **关联规则**：仅修改界面文案、样式等不影响亲属关系与权限的变更，只需更新本文件；涉及关系判定、代际、排行、分支、访问控制的变更，两份文档都必须更新。

#### 统一父系、母系、配偶分支的根节点与层级规则
- 类型：修复 / 优化
- 模块：后端 / 网页端 / 小程序

- 问题现象：
  - 父系分支以最高父系祖先为根，但未把根节点上移的代数计入层级上限；母系、配偶分支会计入。同一个 `levels` 参数在三支中的含义不一致，父系祖先链较深时，中心成员及其后代可能被提前截断。
